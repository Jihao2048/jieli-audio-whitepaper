## 转换出来的声音不对

**症状**：声音变调（偏高/偏低）、速度不对（快进/慢放）。

**原因**：这几乎一定是 **F1A 采样率判断错了**。

F1A 文件里**没有可靠的采样率字段**，而官方解码器更麻烦——它**固定把
16000 写进 WAV 头**，跟真实音频流没有关系。所以采样率只能靠外部信息判断。

**解决**：

1. 估计一下正确值：听起来像**快进**（声音尖）→ 采样率设低了；
   像**慢放**（声音闷、拖沓）→ 设高了
2. 在界面「采样率」下拉里换一个值重新转换
3. 命令行用 `-r`：

```bash
python wav_tool/jie2wav.py 音乐.f1a -r 16000
```

**唯一正确性判据是你的耳朵**。工具默认的 8000 Hz 是实测数据推导出来的，
但不保证适用于所有文件。

如果是 `.a` / `.b` / `.e` / `.ump3` 出现变调，那属于异常情况，
请附上文件信息（`--info` 的输出）提 issue。

## 双击 bat 没反应 / 闪一下就没了

**原因**：没装 Python，或者装的时候没勾 *Add to PATH*。

**解决**：

1. 到 [python.org](https://www.python.org/downloads/) 下载 Python 3.8 或更高版本
2. 安装时**务必勾选 `Add Python to PATH`**
3. 装完重新双击 `启动转换工具.bat`

**验证**：打开命令提示符（Win+R 输入 `cmd`），执行：

```
python --version
```

能打印版本号就说明装好了。

## 提示"无法识别的格式"

工具支持这些扩展名：

```
.f1a  .f1b  .f1c  .a  .b  .e  .ump3
```

**可能的原因**：

1. **扩展名不对** — 文件内容其实是支持的格式，但扩展名被改过。
   试着把扩展名改成正确的再试。
2. **文件损坏** — 传输过程中出错了，重新拷贝一份。
3. **是别的芯片的格式** — 本工具针对杰理 AD14N / SH50 / SH52 系列。
   其它厂商（比如某些 ESP32 音频方案、思必驰等）的私有格式不支持。

**诊断**：用 `--info` 看看文件开头是什么：

```bash
python wav_tool/jie2wav.py --info 你的文件
```

如果开头是 `cb xx bf f0 06 67 72 aa 66 17 f7`，那是标准 F1A 头；
如果开头是别的高熵数据，可能是无头 F1A 或非杰理格式。

## 提示"找不到 MP3 解码器"

`.ump3` 需要 FFmpeg 才能解码（因为它本质上就是 MP3）。

**三种解决方式，任选一种**：

1. **装一个系统 FFmpeg**（推荐）
   - 从 [ffmpeg.org](https://ffmpeg.org/download.html) 下载
   - 解压后把 `bin` 目录加到 `PATH`
   - 验证：`ffmpeg -version`

2. **放到 tools 目录**
   把 `ffmpeg.exe` 复制到 `wav_tool/tools/`

3. **设置环境变量**
   ```
   set JL_FFMPEG=D:\你的路径\ffmpeg.exe
   ```

> 本仓库出于体积考虑没有提交 `ump3_ffmpeg.exe`（34 MB）。
> 如果你拿到的是完整分发包，里面应该已经带了。

**注意**：`.f1a` / `.a` / `.b` / `.e` **不需要** FFmpeg，
它们是纯 Python 实现或使用随包的小解码器。

## 提示"implausible F1A stream"

```
implausible F1A stream: 1234 bytes decoded to 987654 samples
(0.010 bits/sample); the payload does not look like a real coded stream
```

**原因**：官方 F1A 解码器**不校验文件头**，任何数据喂进去它都会"解出"
一些东西。这个检查是用来防止把随机数据当成音频输出的。

正常 F1A 的码率在 0.2–2.0 bit/样本之间。低于 0.2 说明这个文件根本不是
F1A 载荷。

**可能的情况**：

1. 文件不是 F1A（扩展名被误改）
2. 文件被截断或损坏
3. 文件被加密或压缩过

## 转换很慢 / 界面卡住

**正常速度参考**：

| 格式 | 1 分钟音频大约耗时 |
|---|---|
| `.a` `.b` `.e` | < 1 秒 |
| `.ump3` | 1–3 秒 |
| `.f1a` | 3–10 秒 |

F1A 较慢是因为要启动外部解码器进程。

**界面说明**：转换在**后台线程**里跑，界面不会卡死。转换期间：

- 进度条会走动
- 日志实时输出
- 可以点「取消」中断

**如果确实异常慢**：检查是不是被杀毒软件拦截了
`wav_tool/tools/testf1a_dec.exe` 的启动。

## 输出文件和源文件对不上时长

**F1A 会比原文件长一点**，这是**正常现象**：

- 编码器按 256 样本为一帧处理，最后一帧会补齐
- 实测例：16000 样本的源，解码出 16512 帧（多了 512 = 2 帧）

**`.e` 文件**默认会自动对齐到原始起点，所以时长基本一致；
如果你勾选了「保留编码器预热样本」，则会多出约 22 个样本。

## 能不能从 WAV 转回 f1a

**不能，而且本项目有意不做。**

原因是 F1A 用的是**私有频谱编码器**（MDCT 类变换 + 尺度因子 +
频谱游程编码），只有官方工具知道完整算法。本项目完成了：

- ✅ 容器结构完全还原（11 字节头、256 样本/帧、VBR 特性）
- ✅ 解码链路完全打通
- ❌ 帧内参数和 RLE 码字表未能还原

生成这些文件本来是**官方软件的职责**，用原版
`音频文件转换工具_1.2.2.exe` 即可。
